────────────────────────────────────────────────────────────────────────────────
1. WHAT THE TOOL DOES
────────────────────────────────────────────────────────────────────────────────

DRAFT Tool automates migration of content from a legacy Word (.docx) document
into a new document template. The workflow is:

  1. User selects a Source document and a Destination template.
  2. Both are parsed to extract Section objects (heading + content beneath it).
  3. AutoMapper fuzzy-matches source sections to destination sections and
     assigns a confidence score (AUTO ≥ 90%, REVIEW 65-89%, UNMAPPED < 65%).
  4. User reviews the mapping table, overrides destinations, sets migration
     modes (Append / Prepend / Replace), saves/loads profiles.
  5. ContentMigrator writes a working copy of the template and inserts all
     mapped source content colored green (RGB #00B050).
  6. BoilerplateDetector post-processes the output: any green sentence that
     verbatim matches the destination template's boilerplate is recolored blue.
  7. Optionally exports a CSV audit report (one row per section).

4. DATA MODELS  (models/sections.py)
────────────────────────────────────────────────────────────────────────────────

  BlockType (enum)
    PARAGRAPH / TABLE / IMAGE

  MatchMethod (enum)
    EXACT / FUZZY / NONE / MANUAL

  MigrationMode (enum)
    APPEND / PREPEND / REPLACE

  MappingStatus (enum)
    AUTO     — ≥ 90% confidence, auto-accepted, green row
    REVIEW   — 65–89% confidence, user should verify, yellow row
    UNMAPPED — no destination, red row
    MANUAL   — user changed destination from auto-mapper's suggestion, blue row
    SKIPPED  — user explicitly excluded this section, grey row

  Section (dataclass)
    title: str
    heading_level: int             (1–6)
    paragraph_index: int           (position in document.paragraphs flat list)
    content_blocks: list[ContentBlock]
    .display_title (property)      — title with (level-1)*3 leading spaces for UI
    .normalized_title (property)   — stripped of section numbers and punctuation;
                                     used ONLY for fuzzy matching

  MappingResult (dataclass)
    source_section: Section
    dest_section: Optional[Section]          — current (mutable)
    original_dest_section: Optional[Section] — frozen snapshot from auto-mapper
    confidence: float
    match_method: MatchMethod
    status: MappingStatus                    — current (mutable)
    original_status: MappingStatus           — frozen snapshot from auto-mapper
    migration_mode: Optional[MigrationMode]
    top_suggestions: list[tuple[Section, float]]
    .has_user_changed_destination (property) — True if dest differs from original
    .confidence_display (property)           — "87%" or "–"
    .status_icon (property)                  — emoji for Status column

  IMPORTANT: original_dest_section and original_status are set once by the
  auto-mapper and NEVER modified afterward. The UI only touches dest_section,
  status, and migration_mode. Comparing current vs. original is the change
  detection mechanism.

5. HEADING DETECTION  (core/document_parser.py — _get_heading_level)
────────────────────────────────────────────────────────────────────────────────

Three strategies tried in priority order:

  Strategy 1 — Style name prefix
    paragraph.style.name.lower().startswith("heading")
    Extracts the trailing digit → level.
    Catches: "Heading 1", "Heading 2", etc.

  Strategy 2 — Paragraph-level XML <w:outlineLvl>
    Reads <w:pPr><w:outlineLvl w:val="N"/> from the paragraph element.
    val is 0-indexed; add 1 → heading level.
    Catches: custom-named styles where each paragraph has its outline level set.

  Strategy 3 — Style inheritance chain (basedOn walk)
    _heading_level_from_style_chain(paragraph.style)
    Walks current.base_style repeatedly (guarded against circular chains via
    visited set). At each ancestor:
      a) Check if ancestor name starts with "heading" → extract level
      b) Check if ancestor style definition has <w:pPr><w:outlineLvl>
    Catches: custom styles like P_Heading_1_numbered that inherit from Heading 1
    via Word's "Style based on" but have neither a "heading" name nor per-paragraph
    outline level set. This was a confirmed gap that is now fixed.

  MAX_HEADING_LEVEL = 6  (Heading 7–9 are ignored)


────────────────────────────────────────────────────────────────────────────────
6. AUTO-MAPPER  (core/auto_mapper.py)
────────────────────────────────────────────────────────────────────────────────

  Thresholds:
    AUTO_THRESHOLD         = 0.90   → MappingStatus.AUTO
    REVIEW_THRESHOLD       = 0.65   → MappingStatus.REVIEW (0.65–0.89)
    SUGGESTION_MIN_SCORE   = 0.30   → minimum score to appear in dropdown suggestions
    DEFAULT_TOP_N_SUGGESTIONS = 3   → max suggestions per dropdown

  Algorithm per source section:
    1. Normalize source title (strip section numbers and punctuation, lowercase)
    2. Score ALL destination sections (exact match = 1.0, else rapidfuzz
       token_sort_ratio / 100). ALL destinations scored even on exact match
       so suggestion list is complete.
    3. Sort descending. Best candidate determines status.
    4. Collect top_suggestions (up to 3 above 0.30, excluding primary).
    5. Build MappingResult with frozen original fields.


────────────────────────────────────────────────────────────────────────────────
7. CONTENT MIGRATOR  (core/content_migrator.py)
────────────────────────────────────────────────────────────────────────────────

  Key behaviors:
  - Creates a temp copy of the destination template; never touches the original.
  - Builds section boundary index using XML element references (stable across
    insertions), NOT paragraph indices (which shift after each insert).
  - Groups source sections by destination; processes each destination once.
  - Replace exclusivity: only the first source mapped to a destination may use
    REPLACE; subsequent sources are forced to APPEND.
  - All migrated text is colored green (RGBColor(0x00, 0xB0, 0x50) = #00B050).
  - Images: extracted via <a:blip r:embed>, copied as centered bordered image
    with a separate green caption paragraph.
  - List numbering: copies abstractNum XML with fresh non-conflicting numIds to
    avoid numbering collisions between source and destination.
  - Tables: deep-copied at XML level, all runs colored green, borders normalized
    to explicit black so they render regardless of destination stylesheet.


────────────────────────────────────────────────────────────────────────────────
8. BOILERPLATE DETECTOR  (core/boilerplate_detector.py)
────────────────────────────────────────────────────────────────────────────────

  Modes:
    HIGHLIGHT_SENTENCES (default) — color only matching sentences blue
    HIGHLIGHT_PARAGRAPH           — color whole paragraph blue if any sentence matches

  How it works:
  - Parses the template into {section_title: set[normalized_sentence]}.
  - Walks the OUTPUT document; tracks current section heading.
  - For each fully-green paragraph, checks sentences against the section's set.
  - Runs straddling sentence boundaries are SPLIT in XML (deep-copy approach)
    before coloring, preserving all run formatting.
  - Whitespace normalization applied for comparison only; raw text never modified.
  - Only saves the output file if at least one change was made.

  Green color detection: reads XML w:color attribute directly (not python-docx
  font.color.rgb API, which raises AttributeError on inherited/theme colors).

10. MAPPING PROFILES
────────────────────────────────────────────────────────────────────────────────

  JSON format (version 1):
    {
      "version": 1,
      "created_at": "2026-05-11T14:30:00",
      "mappings": [
        {
          "source_title": "1. Introduction",
          "dest_title": "1. Overview",
          "migration_mode": "append"
        }
      ]
    }

  Save: captures current table state. Uses section.title (not display_title)
        for reliable matching.
  Load: matches by exact source_title. If recorded dest_title not found in
        current template, row is left as auto-mapped (skipped count). After
        applying, table is repopulated from scratch so all visual state updates.
  Status restoration: if profile destination matches original auto-mapped one,
        restores original_status (AUTO/REVIEW) rather than marking MANUAL.

12. END-TO-END DATA FLOW
────────────────────────────────────────────────────────────────────────────────

  File selection → AnalyzeWorker:
    DocumentParser(source).parse() → list[Section] with content_blocks
    DocumentParser(dest).parse()   → list[Section] (no content needed)
    AutoMapper(source_secs, dest_secs).run() → list[MappingResult]

  Table interaction → MappingTableWidget:
    populate(results, dest_sections) → builds rows, combos, delegates
    User changes combo/mode → _on_mapping_changed() → countChanged.emit(counts)
    countChanged → migration_tab._on_mapping_counts_changed()
                 → updates status bar labels
                 → if visualizer panel open: update_mappings(results, dest_sections)

  Run Migration → MigrateWorker:
    Re-parse both files fresh (not the cached parser objects)
    ContentMigrator.run() → MigrationReport
    BoilerplateDetector.run() → int (recolored paragraph count)
    MigrationReportExporter.export() → str (CSV path)

  Output document color convention:
    Black  = original template content (untouched)
    Green  = migrated content from source (#00B050)
    Blue   = green text that verbatim matches template boilerplate (#0070C0)

13. KNOWN ISSUES AND GOTCHAS
────────────────────────────────────────────────────────────────────────────────

  Qt separator itemText() returns ""
    QComboBox.insertSeparator() items return "" from itemText(i).
    Any validity check loop must guard with `if text:` or separators will be
    treated as valid item matches. See _SearchLineEdit._revert_if_invalid().

  setCurrentIndex() no-op when index unchanged
    After clearing line edit text programmatically, calling setCurrentIndex with
    the same index does nothing. Use setEditText() to force visual update.

  setLineEdit() Python GC risk
    Qt takes C++ ownership of the installed line edit. Store a Python reference
    on the combo object (combo._search_line_edit = le) to prevent GC.

  Duplicate heading titles in destination
    _build_section_boundary_index() only indexes the FIRST occurrence of each
    heading title. Sections with duplicate titles get content inserted into the
    first one only.

  numId cross-document conflicts
    List numbering uses document-local integer IDs. ContentMigrator copies
    abstractNum with fresh non-conflicting IDs. Malformed numbering XML is
    caught and silently skipped (paragraph migrates without list formatting).

  PyInstaller --onefile startup time
    --onefile extracts to a temp directory on every launch (~10 sec cold start).
    Use --onedir for faster startup at the cost of a folder instead of a
    single file. Startup time is a PyInstaller extraction issue, not the app.

  ⚠️ emoji on macOS status column
    ⚠️ renders as monochrome (invisible on dark backgrounds) on macOS.
    Replaced with 🟡 for the REVIEW status to ensure visibility.

15. WHAT WAS BUILT / RECENT CHANGES
────────────────────────────────────────────────────────────────────────────────

  The following features were built across recent sessions (most recent last):

  a) Three-strategy heading detection
     document_parser.py now walks the <w:basedOn> style inheritance chain
     (Strategy 3) to detect custom styles like P_Heading_1_numbered that
     inherit from built-in Heading styles. Fixes documents where custom
     styles prevented any headings from being detected.

  b) Searchable destination combo with revert-on-focus-out
     Each destination combo has a _SearchLineEdit installed via setLineEdit().
     Typing filters the combo; clicking away without selecting reverts to the
     last confirmed valid selection. Key bug fix: separator items return "" from
     itemText() — guard with `if text:` before validity check loop.

  c) Mapping Profiles (Save / Load)
     JSON profile format (version 1). Saves current table state. Load applies
     saved destinations and modes; unmatched rows keep auto-mapped result.
     Status restoration: reverts to AUTO/REVIEW if user reverts to original dest.

  d) Replace exclusivity rule
     First source mapped to a destination owns Replace mode. All others have
     Replace greyed out. Position-based (not selection-time-based) to prevent
     mode-switching exploits.

  e) Visualize Mapping panel  (gui/mapping_visualizer.py — NEW FILE)
     Toggle button in Step 2 opens a side panel at 60/40 split.
     Shows all source sections (left) and all destination sections (right)
     with bezier connector lines for active mappings.
     Source boxes colored by mapping status; destination boxes green (mapped)
     or blue (unmapped). Updates live on every mapping change.
     Legend bar pinned at bottom of panel (light background, always visible).
     Canvas scrolls; legend stays pinned.

  f) Responsive window sizing
     main_window.py now sizes to 88%×90% of the primary screen by default.
     Hard minimum reduced from 960×860 to 860×600 for 13-14" laptops.

  g) Technical documentation regenerated
     scripts/create_docs.py updated and re-run. Docs at:
